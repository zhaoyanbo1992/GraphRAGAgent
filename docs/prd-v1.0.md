## 1. 产品概述

### 1.1 一句话定位

审计台是一个**面向文档密集型团队的本地知识问答工作台**：上传 PDF / 图片 /
Word / PPT / HTML 文档，系统自动完成"云端解析 → 知识图谱构建"索引流水线，
用户随后以自然语言提问，**每条回答都附带可一键跳回原文的知识图谱引用**。

### 1.2 核心目标

| # | 目标 | 衡量方式 |
|---|------|---------|
| G1 | 让非结构化文档变成可问答的知识，全流程无需人工整理 | 上传到可提问 ≤ 1 次上传 + 自动索引 |
| G2 | **回答可信、可审计**：每个事实断言都能回溯到原文精确位置 | 引用复核通过率 100%（citation.triple_id 存在于 KG 且 fullmd_verbatim == text_span） |
| G3 | 索引过程透明可控：用户随时知道系统在做什么、进行到哪一步 | 任务 8 态状态机可见、失败可断点重试 |
| G4 | 支持多格式、多文档批量接入，覆盖真实办公文档生态 | MinerU 全格式白名单（pdf/图片/office/html） |

### 1.3 处理的业务痛点

| 痛点 | 现状 | 审计台的解法 |
|------|------|-------------|
| **黑盒式 AI 回答不可信**：通用 LLM 问答给不出证据，用户不敢采信 | 复制粘贴 PDF 内容问 ChatGPT，无法核对 | 知识图谱三元组 + 双溯源指针（full.md 字符区间 + 页码/bbox），回答强制引用、点击即达原文高亮 |
| **文档解析门槛高**：表格、扫描件、Office 格式的抽取需要专门工具链 | 手工整理或写一次性脚本 | MinerU 云端解析 + 表格旁路（零 LLM 成本的结构化数值抽取），格式白名单直传 |
| **检索过程不可见**：传统 RAG 只给答案，用户不知道系统查了什么 | 无法判断"没答上来"是没查到还是没读懂 | 问答界面实时展示检索轨迹（实体解析→图扩展→证据核验的工具调用明细与耗时） |
| **长流程任务状态焦虑**：批量文档索引动辄数分钟，失败后只能从头再来 | 进度不明、失败重跑全量 | 8 态流水线状态机（queued→parsing→chunking→extracting→kg_building→done/failed/canceled）+ 阶段级断点续跑 |
| **数值型问题靠语义检索答不准**："Q3 收入是多少"这类问题向量检索常失手 | 向量 RAG 对精确数值/跨行对比弱 | KG-only 双通道：实体解析 + 图扩展直接命中三元组，表格数值来自 HTML 结构化解析 |

### 1.4 目标用户群体

| 用户 | 场景 | 核心诉求 |
|------|------|---------|
| **财务/分析师**（主要） | 上传季报/研报，查询指标数值与同比变化 | 数值准确、引用可核对、表格数据可信 |
| **知识管理/文档运营** | 批量接入团队文档库，维护可问答的知识库 | 多格式支持、批量上传、索引状态一目了然 |
| **研发/评测工程师**（次要） | 评估 GraphRAG 链路效果、排查抽取质量 | 检索轨迹可见、抽取明细可查、产物可下载审计 |

**本期不服务**：需要权限/多租户的团队（无登录体系）、需要多轮复杂对话的场景
（会话仅做记录回放，多轮上下文为后续版本）。

### 1.5 核心场景（User Story）

1. **上传即索引**：分析师拖入 5 份 PDF，看到每份文档的流水线进度，2 分钟后全部"可提问"。
2. **有据问答**：输入"Q3 的总收入是多少？同比增长了多少？"，3 秒内收到
   "Q3 总收入 12.5 billion CNY，同比增长 18.2%"，下方 5 张引用卡，点击第 1 张
   跳到原文红下划线高亮的句子。
3. **图谱探查**：在知识图谱中点击 "Q3" 节点，侧边抽屉列出它的全部关系
   （收入/净利/毛利率），逐条跳原文核对。
4. **失败恢复**：一份 600 页 PPT 解析超时失败，任务页显示失败码，点"重试"
   从断点继续，已完成的解析阶段不再消耗云端配额。

## 2. 产品流程

### 2.1 主流程总览（入口 → 最终目标）

```
┌─────────┐   ┌──────────────┐   ┌────────────────────────┐   ┌──────────────┐
│ ① 文档库 │──►│ ② 索引流水线  │──►│ ③ 文档详情（图谱/抽取/  │──►│ ④ 问答引用回溯 │
│ 上传入口 │   │ 状态监控      │   │ 原文 三视图探查)        │   │ （最终目标）   │
└─────────┘   └──────────────┘   └────────────────────────┘   └──────────────┘
     │                │                        │                        │
 批量上传/校验    8态状态机+断点重试      证据抽屉↔原文高亮互跳      SSE流式+引用卡跳原文
```

用户可以从任意入口进入问答（侧栏"问答"直接提问，或文档详情看完图谱后提问），
但**首次使用的主路径**是 ①→④ 全链路。

### 2.2 流程一：文档上传与索引（① → ②）

| 步骤 | 用户动作 | 系统行为 | 界面反馈 |
|------|---------|---------|---------|
| S1 | 进入文档库页，拖入 1~10 个文件（或点击选择） | **客户端预校验**：扩展名白名单（pdf/图片/office/html）、非空、单文件 ≤200MB、批量 ≤10 | 合法文件进入上传；不合法文件**不上传**，卡片栅格上方出现红批注行：`文件名 + 错误码 + 原因`（如 `virus.exe E_UPLOAD_UNSUPPORTED_FORMAT 不支持的文件格式: .exe`） |
| S2 | 等待提交 | 逐文件生成 doc_id（`{uuid8}_{文件名}`）、创建索引任务，multipart 提交后端 | 跳转到首个任务的流水线页；多文件批次显示"本批次其他任务"互链 |
| S3 | 观察流水线页 | 后端执行 8 态状态机：`queued → parsing（MinerU 云端解析）→ chunking（语义分块）→ extracting（LangExtract 实体抽取）→ kg_building（图谱构建）→ done` | 横向步骤条逐节点点亮（✓/运行中 pulse/✗）；进度条 0→100；每阶段完成后展示产物统计（页数/块数/实体数/三元组数）；顶部等宽计时器显示已耗时 |
| S4a | 索引成功 | — | 完成卡显示统计 + 主按钮"查看文档详情"；**2.5 秒后自动跳转**文档详情图谱视图（可点"留在此页"取消；批次内还有任务在跑时不自动跳） |
| S4b | 索引失败（MinerU 超时/解析失败/LLM 失败） | 状态 → failed，保留已完成阶段的产物 | 红批注错误卡（错误码 + 原始错误信息）+ **[重试]** 按钮；重试从首个未完成阶段断点续跑，不重复消耗已完成阶段的配额 |
| S4c | 用户取消（仅 queued/parsing 阶段可取消） | 协作式取消 → canceled | 状态徽标变灰；说明文案明示"MinerU 云端解析无法撤回，已消耗配额不退" |

**校验规则明细**（与后端 `POST /api/v1/documents` 部分成功语义对齐）：

- 白名单四类：pdf `.pdf`；image `.png .jpg .jpeg .jp2 .webp .gif .bmp`（默认开 OCR）；
  office `.doc .docx .ppt .pptx`；html `.html`（强制 `model_version=MinerU-HTML`）。
- html 文件与用户传入的非 MinerU-HTML `model_version` 冲突时该文件被拒
  （`E_UPLOAD_MODEL_VERSION_CONFLICT`），同批其他文件不受影响。

### 2.3 流程二：文档知识探查（③）

文档详情页为**三视图**结构，共享同一份索引产物，切换不重新加载：

| 视图 | 用户看到 | 可执行操作 |
|------|---------|-----------|
| **知识图谱** | 力导向图：节点=实体（颜色=实体类型，大小=提及次数），边=关系谓词（叙事实线/表格虚线），右上角图例按实际类型动态生成 | 点击**边** → 右侧证据抽屉展示该三元组；点击**节点** → 抽屉列出该实体全部关系（可逐条切换、聚焦节点）；点击空白关闭 |
| **抽取数据** | 上表：全部三元组（ID/头实体/谓词/尾实体/路径徽章/页码/溯源区间）；下表：LangExtract 抽取明细（定位✓/✗、类别、文本、属性） | 点击三元组行 → 证据抽屉 + URL 深链；键盘 Enter 等价 |
| **原文溯源** | 衬线排版的 full.md 原文（标题/段落/表格还原） | 从抽屉/引用卡跳入时：目标句**红下划线高亮 + 滚动居中**，顶部批注条"证据 t_xxx · '原文…' · [← 返回图谱]"；表格路径证据显示 bbox 红框页面示意图 |

**证据抽屉**（三视图与问答共用）内容结构：`triple_id + 路径徽章` →
`头实体 — 谓词 — 尾实体`（实体色块）→ 衬线红下划线引文 → 等宽 meta 表
（source / chunk_id / char_interval_chunk / char_interval_fullmd / page_idx /
bbox_normalized / doc_id）→ 溯源按钮。

### 2.4 流程三：有据问答（④，最终目标）

| 步骤 | 用户动作 | 系统行为 | 界面反馈 |
|------|---------|---------|---------|
| Q1 | 侧栏进入问答页；新会话或从历史会话列表选择 | 加载会话历史（逐组回放消息与引用） | 空会话显示引导空态 + "试试示例问题"按钮（预填示例） |
| Q2 | 输入问题（≤2000 字符），Enter 发送 | 可选文档范围 `doc_ids`（默认全部已索引文档，≤5 个） | 用户消息右对齐气泡；输入框禁用、按钮变**[停止]** |
| Q3 | 观察流式回答 | Agent 检索链路：`kg_entity_lookup`（实体解析）→ `kg_expand`（图扩展）→ `fetch_evidence_text`（证据核验）→ LLM 作答 | **检索轨迹区**实时滚动：◉ 阶段徽标（retrieval/grading/answering）→ ⚙ 工具调用（名称+参数）→ ✓/✗ 结果摘要 + 耗时；**答案区逐句出字**（准流式） |
| Q4 | 阅读回答与引用 | 引用复核：每条 citation 的 triple_id 必须存在于 KG，text_span 以 KG 产物归一 | 答案下方引用卡列表：`[1] 引文（衬线红下划线）+ triple_id · full.md[231:271] 或 bbox · 页码`；底部耗时三段（总/检索/作答） |
| Q5 | 点击引用卡 | 按 citation 类型路由：narrative → 原文页 `?hl=起始,结束&t=`；table → 原文页表格证据卡 | 跳转文档详情原文视图，红下划线高亮 + 批注条；**浏览器后退可回到问答现场** |
| Q6a | 正常结束 | `done` 事件 | 按钮恢复"发送"，消息写入会话历史 |
| Q6b | 中途停止 | 用户点 [停止] / Esc（非输入焦点） | 流中断，消息标记"已中断"，输入框恢复 |
| Q6c | 服务端错误 | `error` 事件（retryable 才显示重试） | 红批注错误卡（code/message）+ [重试] 重发同一问题 |
| Q6d | 无相关事实 | citations 为空 | 答案明示"上下文不足"，不虚构引用（引用空态有专门文案） |

**引用可跳转规则**：`doc_id` 存在且（有 `char_interval_fullmd` 或来源为表格）才可点击；
多文档引用未消歧（`doc_id=null`）时按钮禁用并提示"引用跨文档未消歧"。

### 2.5 辅助流程：系统健康（#/health）

展示整体状态（ok/degraded）+ 检查项卡（SQLite / MinerU Token / DeepSeek Key /
已索引文档数 / 运行中任务 / 队列深度）+ 配置键值表（限制/格式白名单/问答参数/
模型名，**不含任何密钥**）。用于部署后快速自检与演示前确认。

## 4. 关键节点与核心功能交互逻辑

### 4.1 URL 状态分层原则（原型已验证的核心机制）

- **进 hash（可分享/可回退）**：`t=triple_id`（选中三元组）、`n=normalized_name`
  （选中实体）、`hl=start,end`（原文高亮区间）、`sessionId`。
- **留内存（瞬态）**：抽屉开合、图谱物理布局、滚动位置。
- 深链冷启动直接可用：粘贴 `#/doc/xxx/text?hl=231,271&t=t_000001` 打开即高亮。
- 非法 `hl`（越界/非数字/倒序）静默忽略，不报错。
- 同页 query 变化（如图谱选边）**不重渲染页面**，只更新抽屉与 URL——保证图谱
  物理布局不闪断；`location.replace` 用于选中态（不污染历史），跳原文用 push
  （可后退回图谱）。

### 4.2 问答 SSE 事件 → UI 映射（与后端契约逐字对齐）

| 事件 | 次数 | UI 渲染 |
|---|---|---|
| `session` | 恰 1 | 建立回答占位；侧栏会话列表置顶/更新 |
| `status` | ≥0 | 轨迹区阶段徽标（stage: retrieval/grading/answering + node + attempt/detail） |
| `tool_call` | ≥0 | 轨迹项：⚙ 工具名（等宽）+ 参数 |
| `tool_result` | ≥0 | 按 call_id 配对：✓/✗ + 摘要 + 耗时 ms |
| `answer_delta` | ≥0 | 追加正文（`aria-live="polite"`）；自动滚底，用户上滚即暂停跟随并出"↓ 回到底部"浮标 |
| `citations` | ≤1 | 引用卡列表（§4.3） |
| `done` | 恰 1 | 耗时三段；消息持久化；按钮复位 |
| `error` | ≤1 | 红批注错误卡；流关闭 |
| `ping` | 周期 | 忽略 |

约束：同一会话**串行提问**（流进行中禁止再发，与单问单答引擎一致）；`answer_delta`
为准流式（后端 structured output 为整块输出，服务端按句切分推送——PRD 如实标注，
不做逐 token 假承诺）。

### 4.3 引用卡交互规则

```
显示:  [n]  text_span（衬线红下划线）
       triple_id · full.md[start:end] 或 bbox[...] · p{page_idx}（等宽小字）
点击:  有 char_interval_fullmd → 跳 #/doc/{doc_id}/text?hl=s,e&t=tid（原文高亮）
       来源=table_body        → 跳 #/doc/{doc_id}/text?t=tid（bbox 证据卡）
       doc_id 为 null（跨文档未消歧）→ 按钮禁用 + title 提示
```

### 4.4 任务生命周期交互规则

| 前状态 | 动作 | 后状态 | 界面规则 |
|---|---|---|---|
| queued/parsing | 取消 | canceled | 其他阶段返回 409（`E_JOB_NOT_CANCELABLE`），界面隐藏取消入口 |
| failed/canceled | 重试 | queued（attempt+1） | **断点续跑**：已完成阶段（产物已落盘）不重跑、不再耗配额 |
| running | 删除文档 | 409 `E_JOB_RUNNING` | 删除入口禁用 |
| 进程重启 | — | running → failed(`E_JOB_INTERRUPTED`) | 任务页显示可重试错误卡 |

### 4.5 轮询与流式纪律

- 任务轮询：1.5s × 10 次 → 3s 慢速；总超时 30 分钟；连续失败 ≥3 次出黄色降级
  提示条（继续重试）；路由切换立即终止（组件 destroy 清理）。
- 流式：AbortController 贯穿；组件卸载/切会话即 abort；`ping` 心跳不计入 UI。

### 4.6 键盘与无障碍

Skip link「跳到主内容」→ 侧栏 → 主内容；Esc 关抽屉/关移动导航/停止流；
抽屉 `role="dialog"` + 焦点归还；图谱画布提供抽取表作为等价键盘路径并
`aria-label` 说明；步骤条 `aria-current="step"`；全部交互元素为原生
button/a；色对比 ≥4.5:1。

## 5. 整体 UI 规范

### 5.1 设计概念

**"审计台"**：亮色档案风。主题是审计与溯源——每条断言都能划回原文，视觉语言
取自纸质文档的批注世界：冷调纸面、墨蓝正文、批注红专用色。区别于常见深色
数据面板，传递"可核对的档案"而非"炫酷驾驶舱"的可信感。

### 5.2 配色系统

| 角色 | 色值 | 使用规则 |
|---|---|---|
| 纸面 `--paper` | `#EFF2F5` | 应用底色 |
| 卡面 `--card` / `--card-tint` | `#FFFFFF` / `#F7F9FB` | 卡片 / 内嵌区域 |
| 墨蓝 `--ink` / `--ink-2` / `--muted` | `#1B2A3A` / `#43566B` / `#6E7E8E` | 正文 / 次级 / 辅助 |
| 边线 `--line` / `--line-strong` | `#D8DEE5` / `#B9C4CF` | 细边线分层（少阴影，仅两档轻阴影） |
| 主交互 `--ink-blue` | `#2B5D8C`（hover `#1E4668`，浅底 `#E3EDF5`） | 链接、主按钮、选中态、当前导航指示条 |
| **批注红 `--redline`** | `#C4442E`（浅底 `#F9ECE8`） | **仅限**：引用下划线、证据抽屉左缘、错误批注、bbox 标记、溯源跳转按钮。禁止作普通装饰色 |
| 语义色 ok / warn | `#2E7D46` / `#9A6B00` | 成功 / 进行中与降级 |

实体类型配色（图谱节点与实体色块，全局一致）：
metric `#2B5D8C` · period `#B26A00` · currency_value `#2E7D46` ·
percentage `#7B3FA0` · company `#C2447A` · unknown `#6B7A88`。

### 5.3 字体系统

| 栈 | 字体 | 用途 |
|---|---|---|
| 衬线 `--serif` | Songti SC / Noto Serif SC / Georgia | **文档正文与引文**、页标题（品牌记忆点） |
| 无衬线 `--sans` | PingFang SC 系统栈 | 全部 UI 文字（14px/1.65 基准） |
| 等宽 `--mono` | SF Mono / JetBrains Mono | **数据本体**：triple_id、char 坐标、统计数字、错误码、JSON |

字号阶：13 / 14 / 15 / 18 / 22 / 27 / 34px。引文排印：衬线 15–16px、行高 1.8、
红下划线（thickness 1.5–2px、offset 3–4px）。

### 5.4 布局与组件样式

**整体布局**：顶栏 56px（sticky）+ 左侧栏 200px + 内容区（max-width 1280 居中）。

| 组件 | 样式要点 |
|---|---|
| 按钮 | 主按钮墨蓝实底白字；次按钮白底细边线；危险操作红边 ghost（非红实底，留出错误色的严肃性）；尺寸 36px 高 / small 28px |
| 标签 tag | 胶囊形等宽 11px；路径徽章双语义：叙事务实线蓝 / 表格虚线绿（与图谱边样式一一对应）；错误批注 tag 红底红边 |
| 卡片 | 白底 1px 边线 + 10px 圆角 + 单档轻阴影；hover 仅边线变主色 |
| 表格 | sticky 表头 + 行 hover 浅蓝底；可点行带 hover 反馈与键盘焦点 |
| 空态 | 虚线边卡 + 衬线标题 + 一句引导 + 主行动按钮（不使用插画） |
| 加载态 | 骨架条（灰蓝圆角块微呼吸），**不用 spinner**；按钮内三点；运行中节点红点脉冲 |
| 错误/提示 | 红批注卡（错误，含错误码等宽字）/ 黄条（降级）/ 绿条（成功）；文案给出下一步动作（如"重试（断点续跑）"），不道歉不含糊 |
| 证据抽屉 | 白底 + 左缘 2px 批注红 + 轻阴影；内容顺序固定：ID 徽章 → 三元组行 → 引文块引用 → meta 键值表 → 溯源按钮 |
| 步骤条 | 横向节点连线；完成绿实心✓ / 运行中蓝空心脉冲 / 失败红实心✗ |
| Toast | 底部居中深底条，错误类红底，3.2s 自动消失 |

### 5.5 响应式（三档断点）

| 区域 | ≥1280（全量） | 768–1279（紧凑） | <768（移动） |
|---|---|---|---|
| 侧栏 | 200px 文字导航 | 64px 图标栏（title 提示） | 隐藏，汉堡 → 左滑抽屉 + 半透明遮罩 |
| 文档卡栅格 | 3 列 | 2 列 | 1 列，上传区高度收窄 |
| 流水线步骤条 | 横向 | 横向可滚动 | 纵向时间线 |
| 证据抽屉 | 右缘 360px **推挤**内容 | 固定覆盖（max-width 保护） | **底部弹层**：上滑把手、max-height 62vh、整页下滑关闭 |
| 图谱画布 | 全高（视口减头部） | 全高 | 55vh，降低物理迭代次数 |
| 问答会话栏 | 260px 常驻 | 240px 常驻 | 折叠（顶部下拉入口） |
| 原文阅读栏 | 76ch 居中 | 居中收窄 | 全宽 −32px，衬线 16px |
| 表格 | 全列展示 | 全列 | 外层横向滚动，sticky 首列保留关键列 |

### 5.6 动效与可访问性底线

- 动效仅三处：运行中节点脉冲、骨架条呼吸、toast 进入；`prefers-reduced-motion`
  下全部关闭。
- 色彩对比 ≥4.5:1（批注红 on 白 ≈ 4.9:1 通过）；焦点环 2px 主色不隐藏。
- 消息流 `aria-live="polite"`；图标按钮均有 `aria-label`。
